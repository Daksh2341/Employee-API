# Starter review

| # | Where | What is wrong | How you'd notice it | How it was fixed |
|---|---|---|---|---|
| 1 | `compute_late_minutes` | Uses the punch-in's wall-clock date without IST conversion, doesn't apply the strict ten-minute grace rule, and truncates negative values incorrectly. | A punch at 09:40:01 IST should be late by 10 minutes; UTC-host timezone or pre-shift punch changes results. | Convert instant to IST, determine overnight shift day, compare elapsed seconds to 600, then floor whole minutes. |
| 2 | `compute_work_hours` | Python `round` uses banker's rounding and float arithmetic. | A duration exactly halfway between hundredths can round down to an even digit. | Use Decimal and `ROUND_HALF_UP` on whole elapsed seconds. |
| 3 | `compute_overtime` | Treats shift end as same-day, is timezone-naive, and does not enforce the 30-minute minimum. | Overnight shift punch-out is measured against the wrong day; 29 minutes incorrectly counts. | Calculate the correct IST shift end day and apply floor minutes plus the 30-minute threshold. |
| 4 | `health` | Always reports ready without pinging MongoDB. | Stop MongoDB and call `/health`; it still returns 200. | Ping the database and return 503 on failure. |
| 5 | `create_employee` | Duplicate check followed by insert races; MongoDB unique constraint was absent. It also returned a naive timestamp instead of epoch milliseconds. | Concurrent requests can both pass the check; response `created_at` violates the contract. | Add a unique index, map duplicate-key errors to 409, and serialize UTC epoch milliseconds. |
| 6 | `EmployeeIn` | Missing contract validation for code, email, lengths, dates, shift formats, and equal shift times. | Send `emp_code="x"`, malformed email, or identical shift endpoints. | Added strict contract-shaped Pydantic validation. |
| 7 | `list_employees` | `skip=page*page_size` skips page one; total ignores department; no required sort; no page bounds. | First item is missing on page 1 and filtered total differs from filtered items. | Use one filter for count and query, `(page-1)*page_size`, ascending code sort, and bounded query parameters. |
| 8 | `punch_in` | Unknown employee causes a 500; local-time conversion, seconds input, untruncated fractions, overnight date and status validation are wrong; check-then-insert races. | Unknown code, timestamp with milliseconds, overnight shift, or concurrent same-day calls. | Validate epoch milliseconds, truncate to seconds, calculate IST attendance date, check employee/status, and use unique `(emp_code,date)` index as the race-safe guard. |
| 9 | `list_attendance` | Reads and sorts the entire collection in Python; total ignores pagination filters; page offset is wrong; output leaks an `id`; dates/instants aren't normalized; no sort tie-breaker or parameter/date validation. | Large collection is slow/memory-heavy, filtered totals mismatch, first page skips records, or response contains internal identity. | Count and page in MongoDB with filters and stable sort, validate dates, bound pagination, and serialize contract fields only. |
| 10 | Module setup / Mongo client | No idempotent indexes, and connection configuration lacked a readiness timeout. | Fresh seeded database has no uniqueness guarantees; unavailable database stalls requests. | Create needed named indexes at startup and use a bounded server selection timeout. |

I checked the basic work-hours formula and the intended default shift values; those are reasonable once rounding and timezone behavior are made explicit. The `history` default shape is also correct for a new punch-in.
